\begin{abstract}
This note refines the local tensor model in
\emph{Planar Tensor Networks, Braiding, and Interface Invariants}.
Concrete Uni20 values now model the \texttt{Space} concept directly:
\texttt{BlockSpace}, \texttt{IrregularSpace}, \texttt{LocalSpace},
\texttt{QNumSpace}, and \texttt{DenseSpace}.  Ordered
\texttt{Domain<...>} and \texttt{Codomain<...>} values are also implemented.
Space structural data is immutable, while each leg space carries a mutable
string label used by exact compatibility checks.  There is no wrapper such as
\texttt{Space<LocalSpace>} and no globally generated space identifier.  The
categorical distinction between a space and its dual remains independent of
the distinction between a morphism's domain and codomain.  This model reduces
to signed charge bookkeeping for bosonic U(1), while retaining the boundary
data needed by later non-Abelian and braided implementations.
\end{abstract}

\section{Relationship to the Planar-Network Design}

The earlier planar-network note established that:

\begin{enumerate}[nosep]
  \item a tensor stores a local ordered domain and codomain;
  \item a network or contraction plan stores global embedding and
        crossing information;
  \item contraction lowers checked compositions, recouplings, braids,
        and traces to block worklists and numerical kernels.
\end{enumerate}

Those conclusions remain.  This note refines the local boundary
vocabulary and removes two unnecessary ideas: a templated
\texttt{Space<...>} ownership wrapper and a globally coordinated
\texttt{SpaceId}.

Two categorical questions remain independent:

\begin{enumerate}[nosep]
  \item Is the object \(X\) or its dual \(\dual{X}\)?
  \item Does this occurrence appear in the domain or codomain?
\end{enumerate}

A domain and a codomain may each contain primal or dual objects.

\section{Concrete Space Values}

\texttt{Space} is a C++ concept.  A concrete model has copyable value
semantics, exact equality, a string label, and an operation for
replacing that label.  Five models establish the initial vocabulary:

\begin{center}
\begin{tabular}{@{}l>{\raggedright\arraybackslash}p{0.38\textwidth}
                    >{\raggedright\arraybackslash}p{0.28\textwidth}@{}}
\toprule
Type & Structural data & Typical role \\
\midrule
\texttt{BlockSpace}
  & canonical unique \((q,d_q)\) sectors
  & MPS virtual bond \\
\texttt{IrregularSpace}
  & ordered \((q,d_q)\) blocks, including repeats
  & projected bond before repacking \\
\texttt{LocalSpace}
  & ordered local-state charges
  & physical site \\
\texttt{QNumSpace}
  & one irrep label
  & irreducible operator leg \\
\texttt{DenseSpace}
  & symmetry-neutral extent
  & batch or bundled tensor axis \\
\bottomrule
\end{tabular}
\end{center}

\texttt{BlockSpace}, \texttt{IrregularSpace}, \texttt{LocalSpace}, and
\texttt{QNumSpace} also model \texttt{SymmetrySpace}.
\texttt{DenseSpace} deliberately does not: it contributes no quantum
number to the selection rule.

\subsection{Structural immutability}

Sector content, local-state order, irrep, and dense extent are fixed at
construction.  A tensor can therefore retain a space value without
its shape or block interpretation changing behind the storage map.

\texttt{BlockSpace} requires an explicit valid symmetry even when
empty.  It accepts a range of \((q,d_q)\) sectors, requires positive
dimensions and matching symmetries, sorts sectors canonically, and
rejects duplicate quantum numbers.

\texttt{IrregularSpace} also requires an explicit valid symmetry, but
preserves the supplied block order and permits repeated quantum
numbers.  It is useful when projecting out part of a symmetry causes
previously distinct sectors to acquire the same remaining charge.
Regularization coalesces those blocks into a canonical
\texttt{BlockSpace} and records the destination block and degeneracy
range of every original segment.

\texttt{LocalSpace} also requires an explicit valid symmetry.  It
preserves input order and repeated charges because different basis
states may transform in the same sector.  Explicit regularization
coalesces those states into a \texttt{BlockSpace} and records each
state's block index and within-block offset.

\texttt{QNumSpace} carries one valid \texttt{QNum}.  Its symmetry
follows from that value.  \texttt{DenseSpace} carries only a
nonnegative extent.

\subsection{Labels and exact equality}

Every concrete space carries a \texttt{std::string} label.  The empty
string is a valid unlabelled value.  Labels need not be unique,
interned, generated, or coordinated between MPI ranks.

Exact equality compares both structure and label:
\[
  X = Y
  \quad\Longleftrightarrow\quad
  \operatorname{structure}(X)=\operatorname{structure}(Y)
  \ \land\
  \operatorname{label}(X)=\operatorname{label}(Y).
\]

Changing a label does not alter extent, sectors, local-state order, or
stored tensor data.  It does change exact space compatibility.  A
network operation which labels a bond must update both endpoint leg
occurrences.  For example, an MPS may initialize all spaces and then
assign labels \texttt{"0"}, \texttt{"1"}, and so on to the
corresponding bond endpoints.

A future structural relation such as
\texttt{isomorphic\_space(X,Y)} may deliberately ignore labels.
Algorithms must choose exact equality or structural compatibility
explicitly.

\subsection{Why there is no global identifier}

A global identifier would require generation, serialization, and
distributed agreement.  It would also make independently
reconstructed but intentionally compatible spaces unequal unless the
identifier were threaded through every construction path.

The required semantics are already represented by immutable structure
and a user-controlled label.  Values are naturally copyable and
serializable, and an operation may request either exact equality or an
explicit structural conversion.

\section{Object Duality and Morphism Side}

A symmetry-aware tensor is a morphism
\[
  A :
  X_0 \otimes \cdots \otimes X_{m-1}
  \longrightarrow
  Y_0 \otimes \cdots \otimes Y_{n-1}.
\]
Its local boundary is the ordered pair
\[
  \Domain[X_0,\ldots,X_{m-1}],
  \qquad
  \Codomain[Y_0,\ldots,Y_{n-1}].
\]

The implemented \texttt{Domain<Spaces...>} and
\texttt{Codomain<Spaces...>} templates are distinct heterogeneous value
types.  They retain their concrete space types and ordered values, expose
space structure read-only, and permit an individual label to be changed with
\texttt{set\_label<I>()}.  Exact equality includes those labels.  Empty
boundaries represent the tensor unit.

The current factor vocabulary contains concrete \texttt{Space} values.  A
future generic \texttt{Dual<S>} adaptor may extend it once the required
categorical operations are established.  Parallel concrete families such as
\texttt{DualBlockSpace} and \texttt{DualLocalSpace} are unnecessary
unless a future category demonstrates that a generic adaptor cannot
express its semantics.

Duality is involutive:
\[
  \dual{(\dual{X})} \cong X.
\]
For U(1), duality negates charge.  A richer category also owns the
evaluation, coevaluation, pivotal, normalization, and braid data
required to use dual objects.

Every boundary entry is one ordered leg occurrence.  Several
occurrences may carry equal copies of the same space value.  Position,
morphism side, object duality, and label remain distinct properties.

\section{All-Out Boundary and Block Selection}

Selection rules are easiest to state after orienting every boundary
leg outward:

\begin{itemize}[nosep]
  \item a codomain factor \(X\) contributes \(X\);
  \item a domain factor \(X\) contributes \(\dual{X}\).
\end{itemize}

Dualizing a tensor product reverses order.  One canonical all-out
ordering is
\[
  \dual{X}_{m-1}\otimes\cdots\otimes\dual{X}_0
  \otimes Y_0\otimes\cdots\otimes Y_{n-1}.
\]

For bosonic U(1), a block is legal when
\[
  \sum_j q(Y_j)-\sum_i q(X_i)=0.
\]
For an MPS site
\[
  A:L\otimes P\longrightarrow R,
\]
this is the familiar
\[
  q_R=q_L+q_P.
\]

The generic implementation asks the category for invariant channels;
it does not hardcode charge addition.  Multiplicity-free U(1) returns
zero or one channel, while non-Abelian categories may return several
channels and a non-empty coupling descriptor.

\section{Repartition Is Wire Bending}

Moving a factor between domain and codomain is not a raw metadata edit.
It is an explicit wire-bending operation, provisionally
\texttt{repartition}, based on rigid-category isomorphisms such as
\[
  \Hom(A\otimes X,B)
    \cong
  \Hom(A,B\otimes\dual{X}).
\]

The move toggles object duality and may reverse order when several
factors move:
\[
  \dual{(X\otimes Y)}
    \cong
  \dual{Y}\otimes\dual{X}.
\]

For bosonic U(1), this is normally a checked boundary and axis-order
operation.  Other categories may attach phases, twists, pivotal maps,
or recoupling transformations.

Relabeling is separate: it changes exact leg compatibility but does
not bend, braid, permute, or numerically transform a tensor.

\section{Composition and Partial Contraction}

Full contraction is morphism composition:
\[
  A:X\longrightarrow Y,\qquad
  B:Y\longrightarrow Z
  \quad\Rightarrow\quad
  B\circ A:X\longrightarrow Z.
\]

Ordinary composition checks exact equality of the joined space
values, including labels.  A named conversion may instead accept
structurally compatible spaces and introduce an explicit isomorphism.

Partial contraction is tensor product with identities followed by
composition.  A checked planner proves this construction and lowers it
without materializing identity tensors.  Axis positions and explicit
contraction pairs determine which occurrences are joined; labels
validate the intended pairing but do not address or reorder axes.

Global networks use the same primitives: tensor product, association,
recoupling, repartition, symmetric permutation or explicit braid,
composition, and categorical trace.

\section{\texttt{BlockTensor} Consequences}

An illustrative static interface is:

\begin{verbatim}
template <
    class T,
    class DomainType,
    class CodomainType,
    BlockTensorStorage Storage>
class BlockTensor;

template<class T, CompleteBlockStorage Storage>
using AMatrix = BlockTensor<
    T,
    Domain<BlockSpace, LocalSpace>,
    Codomain<BlockSpace>,
    Storage>;

template<class T, SparseBlockStorage Storage>
using MpoSite = BlockTensor<
    T,
    Domain<LocalSpace, LocalSpace>,
    Codomain<LocalSpace, LocalSpace>,
    Storage>;
\end{verbatim}

The static type fixes boundary order, space kinds, and storage requirements.
Each tensor value carries the concrete space values for its ordered leg
occurrences.  Runtime labels distinguish intended bonds, physical legs,
impurities, or alternating site types.

A block key remains extensible:
\[
  \mathsf{BlockKey}
  =
  (\text{sector index per boundary occurrence},
   \mathsf{CouplingDescriptor}).
\]
The coupling descriptor is empty for multiplicity-free U(1), but may
identify an invariant channel or fusion basis later.

\texttt{DenseSpace} is load-bearing rather than merely a degenerate
case.  It permits one block tensor to bundle structurally identical
tensors, such as block-Lanczos vectors, a bundled MPS, or tangent
vectors.  The bundle shares layout metadata and may use coalesced
storage.

\section{Storage Orthogonality}

The same boundary and block keys may use individual host allocations,
offsets in coalesced buffers, CUDA-resident blocks, or MPI-distributed
blocks.  Storage policies choose ownership, allocation, and placement.
They preserve:

\begin{itemize}[nosep]
  \item all concrete space values and labels;
  \item domain and codomain order;
  \item explicit object duality;
  \item sector indices and coupling descriptors;
  \item deterministic block keys used by distributed worklists.
\end{itemize}

Storage movement is not a symmetry transformation.  Dense
materialization is not an implicit fallback for a symmetry-aware
operation.

\section{Decompositions Create Bond Values}

For
\[
  A:X\longrightarrow Y,
\]
an SVD may use
\[
  V:X\longrightarrow B,\qquad
  S:B\longrightarrow B,\qquad
  U:B\longrightarrow Y,
\]
\[
  A=U\circ S\circ V.
\]

The decomposition constructs one bond-space value \(B\), chooses its
sector structure and label, and places equal copies on the
corresponding factor occurrences.  Truncation determines \(B\)'s final
structure before the result is exposed.  QR, LQ, polar decomposition,
and DMRG bond truncation follow the same value contract.

\section{Initial U(1) Implementation Sequence}

The first host-only U(1) \(\BlockTensor\) should:

\begin{enumerate}
  \item use the concrete implemented space models directly;
  \item use the implemented ordered domain and codomain values;
  \item add generic \texttt{Dual<S>} when its required operations are
        established;
  \item derive block legality from the all-out boundary;
  \item keep the block key extensible with an empty coupling
        descriptor;
  \item require exact compatible leg values for ordinary composition;
  \item implement the cheap U(1) form of repartition;
  \item carry all boundary and space metadata through async worklists,
        reduced-block kernels, CUDA lowering, and MPI placement.
\end{enumerate}

\section{Interface Invariants}

\begin{enumerate}
  \item Concrete types model \texttt{Space}; no ownership wrapper is
        required.
  \item Structural space metadata is immutable; the string label is
        mutable.
  \item Exact equality includes the label.
  \item \texttt{BlockSpace} is canonical; \texttt{IrregularSpace}
        preserves ordered segmentation.
  \item \texttt{DenseSpace} is symmetry-neutral.
  \item Every tensor has an ordered domain and codomain.
  \item Object duality is independent of morphism side.
  \item Repartition toggles duality and respects order reversal.
  \item Labels validate compatibility but never determine axis order.
  \item Block selection is an invariant-channel query over the
        oriented boundary.
  \item Global planarity belongs to the network or planner.
  \item Storage movement preserves boundary, space, sector, label, and
        coupling metadata.
\end{enumerate}

\subsection{Required tests}

The initial tests should include:

\begin{itemize}
  \item empty symmetric spaces retaining their explicit symmetry;
  \item canonical unique \texttt{BlockSpace} sectors;
  \item \texttt{IrregularSpace} preserving repeated out-of-order
        blocks and mapping them through explicit regularization;
  \item \texttt{LocalSpace} preserving repeated charges and ordering;
  \item domain and codomain preserving factor types, values, and order;
  \item empty domain and codomain values representing the tensor unit;
  \item exact equality changing when a label changes;
  \item coordinated bond relabeling updating both endpoints;
  \item U(1) MPS and MPO block selection from oriented boundaries;
  \item round-trip repartition and required order reversal;
  \item decomposition factors receiving equal bond-space values;
  \item worklists retaining every block key and complete space value.
\end{itemize}

\section{Conclusion}

The practical rule is:

\begin{quote}
Use concrete immutable space structures with mutable semantic labels,
orient them through explicit domain/codomain and duality, select legal
blocks from that boundary, and leave global planarity to the
contraction planner.
\end{quote}

For bosonic U(1), these rules compile down to value comparisons and
signed charge bookkeeping.  They are suitable for the first host-only
DMRG implementation while preserving the metadata required by CUDA,
MPI, non-Abelian fusion, and braiding.
